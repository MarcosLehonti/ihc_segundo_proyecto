# Evaluación Heurística

## Configuración del Límite de Presupuesto y Registro de Gasto

| # | Pantalla y Evidencia | Problema y Consecuencia | Heurística y Justificación | Severidad |
|---|----------------------|------------------------|---------------------------|-----------|
| 1 | **Registrar Gasto** — `Gastos.tsx` línea 254–259. El campo "Motivo" es `type="text"` pero no tiene validación que impida ingresar solo números (ej. `"123"`). El formulario lo acepta sin error. | El campo acepta valores puramente numéricos, generando registros sin descripción semántica real y dificultando la trazabilidad de los gastos. | **H5 — Prevención de errores** (Nielsen). El sistema debe evitar errores antes de que ocurran. Al no restringir el campo a texto descriptivo, se permite guardar datos inválidos sin advertencia previa. |  3 — Mayor |
| 2 | **Actualización de Presupuesto** — `Dashboard.tsx` línea 116–172. Al presionar "Guardar presupuesto" con un límite ya configurado, `handleGuardarPresupuesto` sobrescribe el valor de forma inmediata sin diálogo de confirmación. | No se solicita confirmación antes de actualizar el límite mensual activo. El usuario puede modificarlo accidentalmente sin posibilidad de cancelar, perdiendo control sobre una acción financiera de alto impacto. | **H3 — Control y libertad del usuario** (Nielsen). El usuario debe poder salir de acciones no deseadas. Al ejecutar la actualización sin confirmación, el sistema elimina esa salida de emergencia en una operación irreversible. |  3 — Mayor |
| 3 | **Registrar Gasto (confirmación de éxito)** — `Gastos.tsx` línea 109–118. Cuando el gasto se registra correctamente, el sistema solo ejecuta `console.log('Gasto registrado correctamente')` (línea 111). No se muestra ningún mensaje visible en pantalla al usuario. | El usuario no recibe confirmación visual de que su acción se completó con éxito. Esto genera incertidumbre y puede provocar que presione el botón varias veces, duplicando registros. | **H1 — Visibilidad del estado del sistema** (Nielsen). El sistema debe informar al usuario sobre lo que está ocurriendo. Al omitir el mensaje de éxito en pantalla, el usuario queda sin retroalimentación tras una acción importante. |  3 — Mayor |
